# 从脚本到像素科普样片

这是一份实际制作记录。公开工程复现的是电梯样例，不是自动理解任意文案的动画生成器。

## 1. 把知识点变成可见的过程

这次的主线是“乘梯 → 发现钢索两端 → 反向运动 → 重量抵消一部分 → 电机仍然工作 → 到站”。

画面里固定轿厢为青色、配重为珊瑚色，始终保留对象身份。用两端相反的位移表现关系，用重量块配对表现部分抵消。不能只把旁白换成几个标题，然后给卡片加位移动画。

## 2. 先获得真实旁白，再确定时间

本次使用 VoxCPM 生成过旁白，并转录词时序；公开版本只保留文案和对应字幕时间，不分发个人声音。别人的声音或同一声音重新生成，停顿都可能变化。字幕时间要重新核对，不能默认照用。

`timing.json` 是 30 秒源时间轴。制作时把脚步、门、运动、配对接触和到站提示绑定到同一条时间轴。先做几个关键动作，再扩展整段。

## 3. 素材要有具体职责

本例实际检索并使用了一段授权电梯井视频，用来从日常电梯进入“背后的钢索与导轨”，随后接剖面示意。来源、作者、剪取区间和修改保存在 `THIRD_PARTY_NOTICES.md`。

项目需要全像素风格时，可以改写这个镜头。不要把“必须插入实拍”当成所有像素视频的固定模板。本例保留该镜头，便于研究视频素材与程序动画如何合成。

## 4. 用绝对时间画帧

所有对象状态都由源时间 `t` 计算，避免靠每帧累加位置。这样向前播放、倒退拖动或并行渲染同一时刻，能得到同一画面。

角色采用七种姿势。环境先画在 480×210 的低分辨率画布，再按整数 4 倍放大；文字用高分辨率画布绘制，避免小字在像素化后不可读。横版构图需要重新安排空间，不能只把竖屏放宽。

## 5. 声音跟动作发生

`synthesize_sfx.py` 使用三角波、脉冲波、噪声、包络和声像生成 28 个事件，随机种子固定。步伐、门的滑动和接触、机械运动、重量配对、摩擦及到站各有声音职责。

基础事件的合成结果保存为 30 秒 SFX 轨。`mix_audio.py` 再独立调整人声与效果声。人声保持原增益，提高效果声后重新检查峰值和听感，不依赖混音器默认归一化把改动抵消。

## 6. 加速要共用时间映射

默认 `rate=1.2`：

```text
输出时长 = 30 / rate = 25 秒
动画的源时间 = 输出时间 × rate
字幕/音效输出时刻 = 源时刻 / rate
音轨变速 = FFmpeg atempo=rate
```

动画与音效同步提速，语音使用 `atempo` 保持音高。实拍片段的可见窗口跟随场景缩短，实拍内容仍按正常速度播放；若要对实拍本身变速，需要另外处理其媒体时间。

## 7. 验证实际编码

至少检查：完整视频/音频解码、1920×1080、帧数、音轨长度、字幕与动作的对应、中段和结尾、素材署名。然后正常速度看完整段、戴耳机听混音，记录具体问题。

`python pipeline.py check` 只执行技术检查。报告中正常速度审看与主观听审保持 `unverified`，不能因为 FFmpeg 返回成功就写成“完整验收”。公开样片也保留这一界限。

## 已知边界

- 这是解释机械关系的简单样片，美术、角色表演和镜头密度仍可继续完善。
- 改主题需要重做叙事与场景；仅修改 `narration.txt` 不会自动生成对应动画。
- 示例的字幕和动作是定制时间轴，没有集成通用语音对齐器。
- 实拍为较低分辨率的剪取片段，可研究合成方法；正式制作可以回到原始高清输入。
- 中文字体由系统提供，不同机器的字形和字宽可能略有差别。
- 本次运行验证以 Windows 为准，其他系统仍需要验证中文字体和 Chromium 环境。
